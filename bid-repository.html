Operations internship, summer 2025

Carrier bid repository

Five years of freight bid files sat in 55 GB of spreadsheets that nobody could search, so the sales team was quoting new business without the history.

The bid files belong to my former employer, so none of the company's files appear here. The code below shows the parsing approach, and the dashboard is a rebuild with invented customers, lanes and volumes.

The problem

Every customer bid arrives as its own workbook, with its own template, column names and number of header rows before the data starts. Once a bid is won or lost, the file goes into a folder and nobody opens it again.

That's a problem when a rep is on a call and wants to know if the company has ever run a lane before, and at what volume. Answering meant opening files one at a time.

How I worked it

I started by asking reps what they needed answered on a call, which came down to lane, customer, volume, miles and year. I chose to parse and normalize the files as they were instead of asking anyone to change how they file bids. Then I did the cleanup, built the Power BI model, sat with reps while they tried it, and fixed the views. I presented it to leadership at the end of the internship and documented the pipeline so new bid files could be added after I left.

The parsing

Most of the work was the parsing. No two bid templates agreed on what to call an origin city, and the header row was rarely the first row. Most files open with a title block, a logo and a blank line, so a script that assumes the first row is the header gives you bad data across thousands of sheets.

So the script scans the first ten rows of every sheet, scores each row on how many known column spellings it has, and treats the best one as the header. The spellings live in a lookup table, so adding a new bid format means adding a spelling. Sheets that can't be matched get reported instead of dropped.

This is the core of the parser:

# Canonical field -> the header spellings seen in the wild.
SCHEMA = {
    "origin_city":  ["origin city", "org city", "city (origin)"],
    "origin_state": ["origin state", "org state", "origin st"],
    "origin_zip":   ["origin zip", "org zip", "origin postal code"],
    "dest_city":    ["destination city", "dest city", "dst city"],
    "dest_state":   ["dest state", "destination_state", "dst state"],
    "dest_zip":     ["dest zip", "destination_zip", "dst zip"],
}


def find_header_row(frame):
    """Return the index of the row that looks most like a header, or None.

    A row qualifies when it contains recognizable spellings for at least
    half the canonical fields. Scanning beats assuming header=0: these
    workbooks routinely open with a title, a logo row, and a blank line.
    """
    best_index, best_score = None, 0
    for i in range(min(10, len(frame))):
        cells = {str(v).strip().lower() for v in frame.iloc[i].values}
        score = sum(1 for spellings in SCHEMA.values()
                    if cells & set(spellings))
        if score > best_score:
            best_index, best_score = i, score
    return best_index if best_score >= len(SCHEMA) / 2 else None


def extract_sheet(frame):
    """Project one sheet onto the canonical schema, filling absent fields."""
    lookup = {str(c).strip().lower(): c for c in frame.columns}
    out = pd.DataFrame(index=frame.index)
    for field, spellings in SCHEMA.items():
        match = next((lookup[s] for s in spellings if s in lookup), None)
        out[field] = frame[match] if match else pd.NA
    return out

Python 3 with pandas. The full pipeline walked a directory, tagged every row with its source file and sheet, and reported unmatched sheets instead of dropping them.

What reps got

Three views, because reps were asking three different questions. This is a rebuild with invented data, and the layout and clicks work the way the real one did.

The first version was one table with every field and a pile of slicers. People couldn't find what they came for, so I split it by the question being asked, and that's the version that got used.

The second piece

Once bid history was searchable, I used the same pattern going forward. Carriers get a standard bid template by email, Power Query pulls the responses in and normalizes them, and new carrier bids file into a Power BI report that pricing and senior leadership use for carrier selection. Getting carriers to send bids back in one format was easier than parsing whatever showed up.

What I took from it

The dashboard was the quick part, and the cleanup took most of the summer. I also learned to test a tool by watching someone use it, since asking people if it looks good doesn't tell you if they can find anything.
